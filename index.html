2º semestre · 2026/2 · Parceiro: DM

Landing page de captação e pré-qualificação de clientes

Em andamento

O problema

A DM recebe solicitações de cartão por canais que não conseguem responder ao cliente na hora. Cada pedido precisa ser confrontado com a base de pré-qualificação para decidir, no momento da solicitação, se ele é aprovado, reprovado ou vai para análise — e, no caso do Cartão Loja, ainda é preciso oferecer apenas as lojas do mesmo estado do CEP informado, entre parceiros que têm mais de mil estabelecimentos. Sem isso, o cliente escolhe uma loja onde o cartão não passa e a captação se perde.

  • Python
  • MySQL
  • Modelagem relacional
  • Levantamento de requisitos
  • User Stories
  • Wireframes
  • Scrum
Regras de negócio e solução desenvolvida

Regras de pré-qualificação acordadas com o parceiro

  • Colaborador da DM — Cartão DM: aprovação automática. Cartão Loja: reprovação automática.
  • Não colaborador — Cartão DM e Cartão Loja passam por análise; quem é considerado apto é aprovado, o restante fica com status em análise.
  • Cartão Loja — só permite escolher unidades no mesmo estado do CEP informado, porque o cartão PL só passa na respectiva unidade.
  • Cartão Loja Digital — captação liberada independentemente do estado, deixando explícito para o cliente que não haverá via física.

Solução — em construção. O semestre está em andamento; esta seção será atualizada com a arquitetura final, o modelo de dados e as capturas da aplicação funcionando assim que a entrega for concluída.

Artefatos previstos na entrega

  • Manual de instalação versionado no Git e manual do usuário.
  • Documentação da API.
  • Modelagem do banco de dados relacional.
  • Vídeo de demonstração das funcionalidades.
  • Interface responsiva validada em telas pequenas.

  • SQLite
  • zod
  • Docker
